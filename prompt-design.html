Prompt Architecture

How the
prompts work

The model never decides what's in the catalogue. Code picks candidate tools, builds a layered prompt around the apprentice's context, and validates the answer before anyone sees it.

Five places we prompt a model
  • AskRecommends tools for a problem, from the catalogue only
  • ModerateChecks reviews against our HN-style guidelines
  • BiasFlags promo language, brigading and suspect scores
  • NormaliseTurns survey answers into catalogue rows
  • LaunchWrites a launch post when a tool goes global

Background prompts run on Nous Research open-weight Hermes models.

Which model gets which prompt

      
Small, frequent, structured jobs go to the cheapest model that passes our eval set. Only open-ended answers go to a larger model. Background jobs run on Nous Research Hermes models on our own hardware.

      Guardrails
      
What keeps answers honest

      
Each rule lives in two places: as an instruction in the prompt and as a check in code. The prompt makes good behaviour likely; the code makes bad output impossible to ship.

    

    

      
Catalogue only
The prompt lists candidate tools by ID. Code drops any recommended ID that wasn't in that list, so the model can't invent tools or links.

      
Reviews are data
User text sits inside <reviews> and <question> tags. The system prompt says text inside them is never an instruction. Try the "Ignore your rules" example.

      
Facts from rows
Cost, limits and scores are copied from the database into the prompt. The model is told to quote them, and code checks that any number in the answer matches.

      
Say when unsure
Unverified tools are marked verified:false. The model must say so, and must return no_good_match rather than stretch a weak fit.

      
Policy flags
Tools with assessment or employer risk carry a flag in their row. The answer has a watch_out field that must mention it.

      
Budget, not truncation
If the prompt is too big, code drops layers in a fixed order: older chat turns, then review snippets, then the 5th tool. System rules and the question are never cut.

    

    

      

        
How we test the prompts

        
    
          
  • A golden set of about 50 real apprentice questions with the tools a senior apprentice would pick.
    • 
          
  • Each prompt change runs the set and scores: valid JSON, catalogue-only, right top tool, flags mentioned.
    • 
          
  • A model grader marks tone and clarity; a person checks a sample each week.
    • 
          
  • Prompt templates are versioned files in the repo, so every answer logs which version wrote it.
    • 
        

      

      

        
How usage improves it

        
    
          
  • Searches, clicks and "not helpful" votes change retrieval ranking in step 3.
    • 
          
  • Questions with no good match become survey prompts and catalogue gaps for admins.
    • 
          
  • Moderation disagreements between model and human reviewer become new golden examples.
    • 
          
  • We never fine-tune on raw reviews; they stay attributable and removable.
